# Feature Specification: Azure DevOps PR Review Comment Exporter

**Feature Branch**: `001-ado-review-export`  
**Created**: January 7, 2026  
**Status**: Draft  
**Input**: User description: "Azure DevOps の 1 リポジトリを対象に、PR のコードレビュー指摘コメント（スレッド/コメント）を収集して、LLM に読ませやすい 1 ファイル JSON としてエクスポートする Windows デスクトップアプリ"

## Background & Context

### Why This Feature?

開発チームは Azure DevOps で PR レビューを日々行っているが、過去のレビュー指摘コメントを体系的に分析できていない。そのため：

- 同じ指摘が繰り返される（属人的な知識に依存）
- チーム全体で共通のレビュー基準が確立されていない
- 品質向上のためのパターン抽出ができていない

過去の指摘コメントを収集・分析することで、共通ルールの抽出や自動チェックの導入が可能になり、品質向上とレビュー速度改善、属人性低減につながる。

### What This Feature Does

Azure DevOps の単一リポジトリから、全 Pull Request のレビューコメント（スレッド/スレッド配下のコメント）を収集し、LLM で分析可能な構造化 JSON（1ファイル）としてエクスポートする Windows デスクトップアプリケーション。

GUI での対話的操作と、CLI でのバッチ実行の両方に対応する。

### What This Feature Does NOT Do (Non-Goals)

- Azure DevOps へのコメント書き戻し（読み取り専用）
- レビューコメントの自動返信や自動承認
- 組織全体や複数プロジェクト横断の一括収集（対象は単一リポジトリ）
- リポジトリ一覧の自動列挙（対象リポジトリは明示的に指定）
- リアルタイムの監視や永続的なデータ同期
- 他の Git サービス（GitHub、GitLab など）への対応
- コメント以外のデータ（ビルド結果、テスト結果、ワークアイテム）の収集

## User Scenarios & Testing *(mandatory)*

### User Story 1 - GUI 操作による単一リポジトリのコメントエクスポート (Priority: P1)

開発チームのリーダーが、過去のレビュー指摘を分析するために、GUI アプリケーションを使って特定リポジトリの全 PR レビューコメントを JSON ファイルとしてエクスポートする。

**Why this priority**: これが本機能の中核であり、最も基本的な使い方。これだけで独立して価値を提供できる。

**Independent Test**: GUI アプリを起動し、Azure DevOps の認証情報とリポジトリ情報を入力して実行すると、指定した場所に JSON ファイルが出力される。LLM にそのファイルを渡すと、過去のレビュー指摘の傾向を抽出できる。

**Acceptance Scenarios**:

1. **Given** アプリが起動している、**When** ユーザーが Organization 名、Project 名、Repository 名、PAT、出力先パスを入力して「エクスポート開始」ボタンを押す、**Then** システムは Azure DevOps API にアクセスし、PR とレビューコメントを収集して、指定した出力先に JSON ファイルを保存し、「完了」メッセージとファイルパスを表示する
2. **Given** エクスポートが実行中、**When** ユーザーが進捗を確認する、**Then** システムは現在処理中の PR 番号と進捗率（例：「50 / 200 PRs 処理済み」）を表示する
3. **Given** Azure DevOps への接続に失敗した（PAT が無効など）、**When** エクスポートを実行する、**Then** システムはエラーメッセージを表示し、エクスポートを中断する
4. **Given** 出力先ディレクトリへの書き込み権限がない、**When** エクスポートを完了しようとする、**Then** システムはエラーメッセージを表示し、ユーザーに別の出力先を指定するよう促す

---

### User Story 2 - CLI によるバッチエクスポート (Priority: P2)

開発チームが定期的に自動でレビューコメントをエクスポートするため、スクリプトや CI/CD パイプラインから CLI コマンドを実行してエクスポートを行う。

**Why this priority**: GUI なしでの実行により、自動化や定期実行が可能になる。P1 の GUI 版と独立してテスト可能。

**Independent Test**: PowerShell やバッチファイルから、コマンドライン引数（Organization、Project、Repository、PAT、出力先）を渡してアプリを実行すると、GUI を表示せずに JSON ファイルが出力される。終了コードで成功/失敗を判定できる。

**Acceptance Scenarios**:

1. **Given** CLI から必要な引数（`--org`, `--project`, `--repo`, `--pat`, `--output`）を指定してアプリを実行する、**When** 実行が開始される、**Then** システムは GUI を表示せず、コンソールに進捗ログを出力しながらエクスポートを実行し、完了時に終了コード 0 を返す
2. **Given** CLI 引数が不足している（例：PAT が未指定）、**When** アプリを実行する、**Then** システムは使用方法（ヘルプメッセージ）を表示し、終了コード 1 で終了する
3. **Given** CLI でエクスポート実行中、**When** ユーザーが Ctrl+C を押す、**Then** システムは処理を中断し、途中までのデータを保存せず、終了コード 130 で終了する

---

### User Story 3 - 投稿者フィルタによる特定ユーザーのコメント抽出 (Priority: P3)

開発チームが特定のレビュアー（例：シニアエンジニア）のコメントのみを抽出して分析したい場合、投稿者名でフィルタしてエクスポートする。

**Why this priority**: 基本機能（P1/P2）が完成していれば、JSON 出力後に LLM 側でフィルタすることもできるため、優先度は低い。ただし、大量データをエクスポート時点で絞り込むことで効率化できる。

**Independent Test**: GUI または CLI で投稿者フィルタ（例：`--authors "user1,user2"`）を指定してエクスポートすると、出力 JSON には指定ユーザーのコメントのみが含まれる。

**Acceptance Scenarios**:

1. **Given** GUI で投稿者フィルタのテキストボックスにユーザー名（カンマ区切り）を入力する、**When** エクスポートを実行する、**Then** 出力 JSON には指定したユーザーが投稿したコメントのみが含まれる
2. **Given** CLI で `--authors "alice,bob"` を指定する、**When** エクスポートを実行する、**Then** alice または bob が投稿したコメントのみが出力される
3. **Given** 存在しないユーザー名でフィルタを指定する、**When** エクスポートを実行する、**Then** システムは警告メッセージを表示するが、エクスポートは続行され、該当コメントがゼロ件の JSON が出力される

---

### Edge Cases

- **大量の PR が存在する場合（1000件以上）**: システムはページング処理を行い、メモリ不足にならないように順次処理する。進捗表示を継続し、タイムアウトエラーが発生した場合はリトライする。
- **レビューコメントが存在しない PR**: PR 情報は収集するが、コメント配列は空として JSON に含める。
- **削除されたコメントやユーザー**: Azure DevOps API が返す情報をそのまま保持する（削除済みフラグや匿名化されたユーザー名も記録）。
- **マルチバイト文字や特殊文字を含むコメント**: UTF-8 エンコーディングで正しく保存し、改行コードや制御文字もエスケープせずに保持する（JSON 文字列としてエスケープ）。
- **ネットワークエラーや API レート制限**: 指数バックオフでリトライ（最大 3 回）を試み、それでも失敗した場合はエラーを表示して中断する。
- **PAT の権限不足**: 最初の API 呼び出しで権限エラーが発生した場合、わかりやすいエラーメッセージ（必要な権限スコープを含む）を表示する。
- **キャンセル操作**: GUI では「キャンセル」ボタン、CLI では Ctrl+C でエクスポートを中断できる。その場合、不完全な JSON は保存しない。

## Requirements *(mandatory)*

### Functional Requirements

**入力・認証**

- **FR-001**: システムは Azure DevOps の Organization 名、Project 名、Repository ID または Repository 名を入力として受け取らなければならない
- **FR-002**: システムは Personal Access Token (PAT) を認証情報として受け取らなければならない
- **FR-003**: システムは PAT をメモリ上でのみ保持し、ディスクやログに永続保存してはならない
- **FR-004**: システムは PAT に必要な最小権限スコープ（`vso.code` の Read 権限）を初回接続時に検証し、不足している場合はエラーメッセージで通知しなければならない

**データ収集**

- **FR-005**: システムは指定リポジトリの全 Pull Request を取得しなければならない（オープン・クローズ・破棄を含む全ステータス）
- **FR-006**: 各 Pull Request について、以下の情報を収集しなければならない：
  - PR 番号、タイトル、説明、作成者、作成日時、更新日時、ステータス（Completed/Abandoned/Active）
  - ソースブランチとターゲットブランチ
  - レビュー結果（承認/却下/保留）
- **FR-007**: 各 Pull Request のレビューコメントスレッドを全件取得しなければならない
- **FR-008**: 各スレッドについて、以下の情報を収集しなければならない：
  - スレッド ID、ファイルパス、行番号（存在する場合）、ステータス（Active/Fixed/Closed など）
  - スレッド内の全コメント（投稿者、投稿日時、コメント本文、親コメント ID）
- **FR-009**: コメント本文は元のテキストを改行・空白を含めてそのまま保持しなければならない（Markdown や HTML として解釈しない）
- **FR-010**: システムは Azure DevOps API のページング（継続トークン）を正しく処理し、全データを漏れなく取得しなければならない

**フィルタリング（オプション機能）**

- **FR-011**: ユーザーは投稿者名（複数指定可、カンマ区切り）でコメントをフィルタできなければならない
- **FR-012**: フィルタが指定された場合、出力 JSON には該当するコメントのみが含まれるが、PR 情報は全件保持されなければならない

**出力**

- **FR-013**: システムは収集したデータを単一の JSON ファイル（UTF-8 エンコーディング）として出力しなければならない
- **FR-014**: JSON ファイルには以下のメタ情報を含めなければならない：
  - エクスポート実行日時（ISO 8601 形式）
  - 対象リポジトリ情報（Organization、Project、Repository）
  - 総 PR 数、総コメント数、総スレッド数
  - アプリケーションバージョン
  - 適用されたフィルタ条件
- **FR-015**: JSON スキーマは後方互換性を考慮し、将来のバージョンで新フィールドが追加されても既存フィールドの構造は変更しないこと（新規フィールドは追加のみ）
- **FR-016**: 出力ファイルパスはユーザーが指定でき、デフォルトはカレントディレクトリに `ado-review-export-{timestamp}.json` という形式で保存されなければならない

**UI/UX（GUI モード）**

- **FR-017**: GUI は Organization、Project、Repository、PAT、出力先パス、投稿者フィルタ（オプション）の入力フィールドを提供しなければならない
- **FR-018**: エクスポート実行中は進捗バー、処理中の PR 番号、進捗率（例：「50 / 200 PRs 処理済み」）を表示しなければならない
- **FR-019**: エクスポート完了時には成功メッセージと出力ファイルパスを表示し、ファイルを開く/フォルダを開くボタンを提供しなければならない
- **FR-020**: エラー発生時には、ユーザーにわかりやすいエラーメッセージ（原因と対処方法を含む）を表示しなければならない
- **FR-021**: ユーザーはエクスポート実行中に「キャンセル」ボタンで処理を中断できなければならない

**CLI モード**

- **FR-022**: アプリケーションはコマンドライン引数（`--org`, `--project`, `--repo`, `--pat`, `--output`, `--authors`）を受け取り、GUI を表示せずにエクスポートを実行できなければならない
- **FR-023**: CLI モードでは標準出力に進捗ログ（処理中の PR 番号など）を出力しなければならない
- **FR-024**: CLI モードは成功時に終了コード 0、エラー時に終了コード 1 を返さなければならない
- **FR-025**: `--help` オプションでコマンドラインの使用方法を表示しなければならない

**エラーハンドリング・信頼性**

- **FR-026**: Azure DevOps API への接続エラー（タイムアウト、レート制限）が発生した場合、指数バックオフで最大 3 回リトライしなければならない
- **FR-027**: リトライ後も失敗した場合、エラーメッセージを表示してエクスポートを中断しなければならない（部分的な出力ファイルは保存しない）
- **FR-028**: システムはキャンセル操作（GUI のボタン、CLI の Ctrl+C）に対して即座に応答し、不完全なファイルを残さないこと
- **FR-029**: 大量の PR（1000件以上）を処理する場合でも、メモリ使用量が過度に増加しないように、ストリーミング処理またはバッチ処理を行わなければならない

**セキュリティ・プライバシー**

- **FR-030**: PAT はメモリ上でのみ保持し、ログファイルやエラーメッセージに出力してはならない（マスク処理を行う）
- **FR-031**: 出力 JSON にはユーザーの PAT や認証情報を含めてはならない
- **FR-032**: システムは Azure DevOps に対して読み取り専用のアクセスのみを行い、データの変更・削除を行ってはならない

### Key Entities *(include if feature involves data)*

- **PullRequest**: 1 つの Pull Request を表す。PR 番号、タイトル、説明、作成者、作成/更新日時、ステータス、ソース/ターゲットブランチ、レビュー結果、関連するコメントスレッドのコレクションを持つ。
- **CommentThread**: 1 つのレビューコメントスレッドを表す。スレッド ID、ファイルパス、行番号、ステータス、スレッド内のコメントのコレクションを持つ。PR に属する。
- **Comment**: 1 つのコメントを表す。コメント ID、投稿者、投稿日時、コメント本文（Markdown/プレーンテキスト）、親コメント ID（返信の場合）を持つ。CommentThread に属する。
- **ExportMetadata**: エクスポートのメタ情報を表す。実行日時、対象リポジトリ情報、総件数（PR/スレッド/コメント）、アプリバージョン、適用フィルタを持つ。
- **Repository**: 対象リポジトリを表す。Organization 名、Project 名、Repository ID、Repository 名を持つ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーは GUI で 5 分以内に初回エクスポートを完了できる（リポジトリ情報の入力からファイル出力まで、100 PRs 以下の場合）
- **SC-002**: システムは 1000 件の PR とそのコメントを 30 分以内にエクスポートできる（通常のネットワーク環境下）
- **SC-003**: 出力された JSON ファイルを LLM（ChatGPT、Claude など）に読み込ませ、「過去のレビュー指摘で多かった項目トップ 10」を抽出できる（構造化データとして解析可能）
- **SC-004**: CLI モードでスクリプトから実行した場合、終了コードで成功/失敗を判定でき、自動化パイプラインに組み込める
- **SC-005**: エクスポート完了後、出力ファイルに対してユーザーが手動で追加の変換・加工を行わずに、そのまま LLM に渡せる（UTF-8 テキストとして読み取り可能、特殊文字のエスケープが正しい）
- **SC-006**: ネットワークエラーや API レート制限が発生した場合でも、90% 以上のケースでリトライにより自動復旧してエクスポートを完了できる
- **SC-007**: 大量の PR（1000件以上）をエクスポートしてもメモリ使用量が 2GB 以内に収まる（メモリリークやクラッシュがない）
- **SC-008**: セキュリティ監査で PAT がログやファイルに漏れないことが確認できる（ログファイルを検索しても PAT が見つからない）

## Assumptions

1. **Azure DevOps API の安定性**: Azure DevOps REST API v7.0 以降が利用可能で、PR とコメント取得のエンドポイントが安定していることを前提とする。
2. **PAT の有効期限**: ユーザーが提供する PAT は有効期限内であり、必要な権限（`vso.code` Read）を持っていることを前提とする。
3. **ネットワーク環境**: ユーザーは Azure DevOps にアクセス可能なネットワーク環境（プロキシ設定が必要な場合は OS のシステムプロキシ設定を使用）にいることを前提とする。
4. **Windows 環境**: 本アプリケーションは Windows 10 (21H2) 以降で動作することを前提とする。
5. **データ量の想定**: 通常のリポジトリは PR 数が 10〜1000 件程度、コメント総数が 1 万件以下であることを想定する。極端に大きいリポジトリ（PR 数 10,000 件以上）ではパフォーマンスが低下する可能性がある。
6. **LLM の入力サイズ制限**: 出力 JSON のサイズは一般的な LLM のコンテキストウィンドウ（数十〜数百 MB のテキスト）に収まる範囲を想定する。巨大な JSON の場合、ユーザーが分割して LLM に読み込ませる必要がある。
7. **投稿者名の一意性**: Azure DevOps のユーザー名（displayName または uniqueName）は組織内で一意であることを前提とする。
8. **JSON スキーマの進化**: 初期リリース後もスキーマの後方互換性を維持し、新しいフィールドは追加のみで既存フィールドの型や名前は変更しないこととする。

## Future Enhancements (Out of Scope for Initial Release)

以下は初期リリースには含まれないが、将来的に検討可能な拡張機能：

- **期間フィルタ**: 特定の日付範囲（例：過去 6 ヶ月）の PR のみをエクスポート
- **PR ステータスフィルタ**: オープン中、マージ済み、破棄済みなど、特定ステータスの PR のみを対象にする
- **除外ルール**: 特定のブランチパターン（例：`hotfix/*`）や特定のレビュアーを除外する
- **複数リポジトリの一括エクスポート**: Organization 内の全リポジトリや、複数のリポジトリをまとめてエクスポート
- **差分エクスポート**: 前回エクスポート以降に追加/更新されたコメントのみを取得（増分エクスポート）
- **エクスポート履歴管理**: 過去のエクスポート結果を管理し、再実行や比較を容易にする
- **カスタム JSON スキーマ**: ユーザーが出力スキーマをカスタマイズ（必要なフィールドのみを出力）
- **他の形式への出力**: CSV、Markdown、SQLite など、JSON 以外の形式でエクスポート
- **リアルタイム通知**: 新しいレビューコメントが投稿されたら自動でエクスポートを実行
- **Web API モード**: アプリケーションを Web サーバーとして起動し、HTTP リクエストでエクスポートを実行
